UT-006 đi qua refresh thật, dùng các trạng thái sai để chặn trước issueTokens. UT-007 kiểm binding token với claims.sub/claims.sid, lock user, revoke session, revoke đúng refresh chưa revoke, tạo AuthorizationChangedEvent.v2 và invalidate cache sau transaction. Session thiếu/đã revoke vẫn success theo source.

Luồng lưu: controller.saveAnswer → service.saveAnswer → saveDraft → lock/record/owner/editable → status/deadline → validateChoices → drafts.write. validateChoices dùng Set để tìm duplicate, find để kiểm snapshot membership và some để kiểm option. selectedOption=null được phép, không giống thiếu thuộc tính.

Đúng/sau deadline, saveDraft gọi finalize bằng draft đã lưu rồi trả 409 cho yêu cầu save. Read draft lỗi phải hoãn hoàn tất, không chấm bằng dữ liệu rỗng thay thế. Submit mặc định có thể finalize blanks; submit đã kết thúc trả record cũ.

Điểm nhạy cảm: <= ở cutoff; updateMany.count!==1 ở refresh; token/user/session binding độc lập; enum DTO rộng A/B/C/D không thay membership của Part 2 chỉ A/B/C; một phần batch hợp lệ không được ghi trước khi kiểm xong batch.
