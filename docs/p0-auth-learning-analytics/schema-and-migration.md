# Schema đích và mapping migration

Đây là thiết kế, chưa có SQL DDL/Prisma migration mới. Service dùng database riêng (`auth_db`, `learning_db`, `analytics_db`) trong PostgreSQL; tên `auth_db.users` trong Word là ký hiệu sở hữu, không mặc nhiên tạo schema PostgreSQL tên auth_db bên trong DB cùng tên. Migration hiện tại tạo bảng ở schema mặc định. Không join hoặc FK giữa các DB.

Index bổ sung: user status; reverse role_code; session user/expiry; refresh user/expiry và hash unique; audit actor/time + target/time; pending sync theo user (unique partial khi status=PENDING); operation status/createdAt; projection user/entity cursor; inbox event ID.

CHECK: versions không âm và resolved≤accepted, applied≤resolved khi tiến watermark liên tiếp; pending FK cùng user; chỉ APPLIED/REJECTED có resolvedAt; không có hai pending một user. Role/status và last admin invariant phải khóa đúng phạm vi khi có race.

## Outbox chung và media

Mọi producer có outbox thiết kế ADR 0022; chỉ viết adapter schema cho Prisma đúng `outboxEvent`, không giữ `as never` để giấu delegate sai. Inbox và nghiệp vụ cùng transaction. Auth authorization-changed, Learning sync result/progress/activity và Exam completion đều dùng envelope V2/routing riêng.

Upload ticket lưu service-local resource/owner, key, content type/size, expiry, confirmedAt; same confirm không attach lại file khác. DB giữ key; object bytes ở MinIO. Prefix policy Auth `toeic-user/avatars/*`, Learning `toeic-media/learning/*`; Analytics không có MinIO credential. Có pending upload cleanup; xóa media chỉ sau khi hết tham chiếu/retention và không thực hiện trong migration.

## Trình tự và gate migration

1. Chạy SQL inventory theo từng DB với transaction READ ONLY; lưu kết quả aggregate, không export PII/token/hash. Dữ liệu không rõ mapping phải có danh sách xử lý cụ thể trước DDL.
2. Backup và diễn tập restore bản sao; thêm bảng/cột/index mới theo migration riêng từng service. Không sửa file migration init đã tồn tại, không reset DB và không `db push` vào dữ liệu thật.
3. Backfill theo batch có checkpoint và provenance. Phát hiện collision/role lạ/URL ngoài allowlist/score thiếu dữ liệu thì quarantine, không tự merge/xóa.
4. Deploy code tương thích và contract V2 riêng; migrate client fields theo OpenAPI; giữ old projection read-only tới khi đối soát xong. Refresh token cutover có thông báo login lại.
5. Đối soát ID/count/relation, constraints, completedAt/date chuyển timezone, head bootstrap và thống kê. Backfill không tự phát learning activity mới để tạo streak/firstLearned giả.
6. Chuyển read path và producer; chỉ xóa cột cũ ở release sau. Rollback app dựa trên schema additive; sau bước không đảo được dùng forward fix/restore đã diễn tập, không drop dữ liệu để “rollback”.

Inventory thật, backup/restore rehearsal và DDL là gate trước migration P2/P3/P5; P0 hiện chỉ hoàn thành mapping/schema contract. Docker chưa sẵn sàng không được diễn giải thành DB trống hoặc dữ liệu an toàn để chuyển đổi.
